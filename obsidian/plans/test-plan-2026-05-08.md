## Key Interactions to Verify (Phase 1.0 + 1.1)

- **Asking a diagnostic** in web chat: type question → see streaming token-by-token response → see citations linking to source SP-API data → see uncertainty markers ("I'm 70% on this") on inferred claims
- **Reacting** to a diagnostic: click 👍 / 👎 / 🎯 / ❓ / 🔁 emoji → reaction persists → eval set updated (👍 candidate, 👎 flagged for review)
- **Free-text feedback**: "tell me what was wrong" input → captured to eval signal
- **LWA OAuth onboarding**: click "Connect Amazon" → redirect to Amazon LWA → grant scopes → return → see backfill progress → first useful diagnostic available within 60 minutes for Orders/FBA questions, 4-24h for Brand Analytics/SQP
- **First diagnostic** flow: complete signup → connect SP-API → wait for backfill → ask first question → get answer
- **Audit log view** (admin): see every tool call + every diagnostic + every memory mutation; see hash chain integrity badge

## Edge Cases (every Phase 1.1 page)

- New seller, <14 days SP-API history → agent says "I don't have enough history"; never pretends
- SP-API token expired mid-diagnostic → silent refresh, retry once
- SP-API endpoint 503 → fallback to cached data + visible note in answer ("Brand Analytics unavailable; using yesterday's snapshot")
- All SP-API calls fail → `[FAILED_NO_DATA]` state, agent says "Amazon SP-API is having issues, retry in 5 min"
- Tenant lacks permission for an SP-API endpoint → agent surfaces explicit re-grant link
- LLM timeout → return partial answer with "Want me to keep going?"
- LLM refusal → re-prompt once with safer framing; if still refused, admin alert
- Stale cache (>24h on cold reports) → flagged to user, never silently stale
- Submission with stale CSRF → re-issue token, prompt to retry
- Slow connection (10+ sec for SP-API report poll) → progressive UI: planning → fetching → reasoning → drafting → streaming
- Concurrent diagnostics from same tenant → both run, memory writes serialized via per-tenant lock
- Same question submitted twice quickly → second deduplicates to in-flight result
- Reaction on web chat → eval set updated only once per (user, diagnostic, reaction) tuple

## Critical Paths (Phase 1.0 + 1.1)

1. **Founder asks first diagnostic against own Nutragroup data** — Phase 1.0 dogfood validation. Ask "why are SKU-X sales down this week?" → agent plans → fetches Brand Analytics + SQP + Orders → drafts honest-voice answer with citations → streams to founder. Latency p50 <60s.

2. **Cross-tenant isolation under load** — Phase 1.1 critical security path. Tenant A asks question → check that prompt builder uses tenant_A's tenant_id only → check that memory retrieval scoped to tenant_A → check that cached SP-API response keyed by (tenant_A, query, day) → tenant_B asking same question hits different cache key. Zero leakage.

3. **Eval rig nightly regression** — Phase 1.1 brand-promise validation. 60-question golden set runs against current prod prompt → judge model scores each → diff vs 7-day baseline → alert on score drop >0.5 → alert on judge variance >0.5 stdev (judge silently broken).

4. **Reaction pipeline closing the loop** — Phase 1.1 self-improving claim. CEO reacts 👍 on diagnostic → flag added to gold-standard candidates → next nightly run, candidates surfaced in admin/eval UI for promotion to golden set. Self-improvement is real, not theater.

## Phase 2.0 Critical Paths (lock now per scope decision)

5. **Listing replication HITL batch** — CEO clicks "Replicate to Walmart" for catalog → agent reads Amazon catalog → hybrid mapping (deterministic 70% + LLM-assisted 30% + untranslatable detection) → drafts 47 listings → batches into 10 → CEO approves batch 1 → check that approved listings actually post via Walmart Item Setup API → check that untranslatable attributes escalate explicitly to CEO with "use closest equivalent or omit?" choice → check decision memory persists ("for category X going forward, omit attribute Y on Walmart").

6. **Cross-channel inventory sync** — Amazon FBA shipment event → buffer recalculated → Walmart/Shopify/eBay channel inventory updated within <30s → never overshoot Amazon FBA available count → velocity-aware buffer adjusts under high-volume periods (recycles prior Copio "never oversell" thesis).

7. **Order convergence + daily written summary** — orders flow in from N channels → unified orderbook view in admin → daily written summary at 7am: "47 orders yesterday: 32 Amazon, 11 Shopify, 3 Walmart, 1 eBay. Stand-out: Walmart conversion up 40% vs last Tuesday."

8. **Return classification + drafted response** — return event from any channel → classifier reads reason text → classifies (defective / wrong-item / customer-changed-mind / sizing) → drafts response in honest persona voice → CEO approves with 1 tap → response posts via channel API.

## LLM Evals Required (eval rig as the moat)

- Honest-voice consistency (uncertainty markers, "I can see" vs "I infer")
- Citation accuracy (every quantitative claim links to source SP-API data)
- Causal narrative coherence (cause → effect chain holds)
- Voice consistency (named persona drift detect, sample 10/week)
- Cross-tenant contamination probe (sentinel strings injected; verify no leak)
- Cache-hit-rate verification (≥80% on repeated context)
- Phase 2.0: classification accuracy ≥85% on held-out return-reason set
- Phase 2.0: untranslatable-attribute detection accuracy
- Phase 2.0: hybrid mapping LLM-assisted output meets target schema
- Phase 2.0: drafted return response in voice + factual

## Test Pyramid Targets

- **Unit**: 200+ tests on tools, parsers, memory ops, prompt builders, mapping rules (Phase 2.0)
- **Integration**: 50+ tests on SP-API client (mocked + real sandbox), Slack client (Phase 1.5), eval pipeline, multi-tenant isolation
- **Eval**: 60 golden questions Phase 1.1 (start at 20 for Phase 1.0); nightly regression
- **E2E (Playwright)**: 14 scripted user journeys (sign-up → connect → first diagnostic; reaction → eval signal; admin audit-log integrity)
- **Chaos**: weekly fault injection — SP-API 503 storm, LLM timeout, DB pool exhausted, judge model variance

## Ship-Readiness Bar (2am Friday test)

- Eval score ≥8.5/10 on 60-Q golden set, no individual case <7.0
- Cross-tenant contamination probe: zero hits last 7 nightly runs
- Cache-hit rate ≥80% on repeated context
- p99 diagnostic latency <180s (fast path <30s, deep path <60s typical)
- Last 24h error rate <0.5%
- Audit log hash chain verified continuous (no row tampered)
