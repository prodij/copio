## Problem Statement

CEOs of $1M–$50M Amazon-native D2C/CPG brands spend hours per week interpreting Brand Analytics + Search Query Performance + ad spend + 3PL data + Slack threads into a story. The recurring "why did X happen this week?" question gets answered slowly (founder writes their own Monday memo), badly (a junior analyst makes a deck nobody reads), or expensively (an agency writes a memo with incomplete data context). Nobody is happy. The data exists. The interpretation does not.

The product is the interpretation, written in honest prose with citations, on demand, by an agent that already read everything. The MVP scope is a single capability of that agent: **diagnostic on demand** — ask "why is X happening with my Amazon business?" get a written causal narrative + linked evidence in <90 seconds, in a consistent persona voice, calibrated for honesty.

## Demand Evidence

Honest accounting:

- **Founder is user 1** with real revenue (7-figure Amazon Nutra brand, Nutragroup) and real SP-API access. The founder's own pain is the demand signal for Phase 1.0. This is the PG "build for yourself" path — necessary but not sufficient. It is real, observable behavior (founder will use it daily), not asserted interest.

## Status Quo

What CEOs of $1M-$50M Amazon brands do today to answer "why is X happening?":

1. **Self-serve interpretation** (most common at <$5M): CEO opens Brand Analytics, opens Helium 10, opens ad console, opens 3PL dashboard, swivel-chairs between them, writes their own narrative. 2-4 hours per question. Answer is partial, biased toward the data they already had open.
2. **Junior analyst** (more common $5M+): hire $60-90k analyst, get Monday morning deck, deck answers questions nobody is asking, real questions asked over Slack still take hours.
3. **Agency** ($10M+): pay $5-15k/mo, get a Monday memo written by someone who doesn't have full SP-API access, real-time questions still go unanswered.
4. **Just don't ask the question.** Most common at every scale. CEOs let things slide because the cost of finding out is too high.

The status quo cost is real. The product replaces hours of swivel-chair labor with a 90-second answer.

## Target User & Narrowest Wedge

**Target user**: CEO/founder of a $1M-$50M Amazon-native D2C or CPG brand. Hands-on operator. Has SP-API access (or can get it). Currently stitches Brand Analytics + tools + spreadsheets to answer "why" questions. Pays for time, not data.

**Narrowest wedge** (validated against alternatives in office hours, premise 2 held):
*Ask-anything diagnostic against deepest-possible Amazon SP-API, in a honest persona voice with citations and uncertainty markers.*

Considered narrower wedges and rejected:
- *Weekly auto-Brand-Analytics-narrative*: $49/mo, 2-day ship, lower activation friction. Rejected because the user explicitly wants "ask anything" framing — it's the unique capability and the founder's mental model of what makes Copio different.

## Constraints

- **Read-only** in MVP (Phase 1.0 + 1.1). No T2/T3 write actions until Phase 1.6 — keeps Amazon AI Agent Policy compliance burden minimal.
- **Multi-tenant from day 1 of Phase 1.1** (single-tenant Phase 1.0 only). Lift auth/tenancy from prior `.deprecated/api/`.

## Approaches Considered

### Approach A: Build Phase 1.0 as designed (chosen)
Single-tenant against Nutragroup, web chat only, 20 founder-authored golden questions, manual eval, ~4-5 CC days. Founder-as-user-1 is the validation mechanism for week 1. External paid commitments gate the Phase 1.1 multi-tenant productization.

### Approach B: 5 concierge diagnostics first (rejected by founder)
Talk to 5 CEOs before any code, charge $99/answer, manually deliver via Claude + SP-API. Validates Premise 1 with money, surfaces customer vocabulary. Rejected because the founder IS the user — internal dogfood is the validation mechanism for week 1, not external concierge.

### Approach C: Manifesto MVP (rejected by founder)
Skip code week 1, publish "The Honest Diagnostic" manifesto on copio-webpage, surface inbound demand as signal. Rejected for the same reason as B — founder dogfood beats inbound for the founder's specific situation.

### Approach D: Combination concierge + build (rejected by founder)
Founder takes calls while CC builds. Rejected; founder's chosen path is dogfood-first.

## Recommended Approach

**Approach A, with the explicit founder-as-user-1 framing**: ship Phase 1.0 against Nutragroup in 4-5 CC days, watch own usage daily for 2 weeks, instrument internal usage telemetry (questions asked, answers retained, decisions taken because of an answer), then promote to Phase 1.1 when (a) the founder's own usage shows real value (questions answered that they couldn't easily answer otherwise, decisions taken because of an answer) AND (b) 3 external CEOs commit to pay $199-499/mo for early access.

This is the PG "build for yourself" path with explicit gating criteria for promotion to external launch.

## Phase 2 Vision — Amazon as the source of truth (added in revision 2)

The Phase 1 wedge (diagnostic agent) earns the trust that unlocks Phase 2 — the strategic move that transforms Copio from "agent that answers" to "infrastructure for the operator."

**The claim:** Amazon listings carry the richest, most structured product data any seller maintains (A+ content, brand-registry attributes, search-relevance metadata, FBA logistics). Sellers expanding to Shopify/Walmart/eBay/TikTok currently re-create this data N times because every tool treats each channel as independent. **Treat Amazon as canonical, and every other channel becomes a derived view that the agent can replicate, sync, and operate against.**

**Phase 2 capabilities** (concrete):

| Capability | Pain it kills | Mode |
|---|---|---|
| Listing replication: Amazon catalog → drafted Walmart/Shopify/eBay listings with attribute mapping + image sets + descriptions in voice | Manual recreation across N channels per SKU, hours of form-filling | HITL — agent drafts in batches of 10, CEO approves |
| Inventory sync: real-time Amazon FBA + FBM → per-channel velocity-aware buffers (recycles the prior Copio "never oversell" thesis) | The 3am oversell panic; manual spreadsheet reconciliation | Auto with anomaly alerts |
| Order convergence: unified orderbook across all channels; agent triages and groups | "Where are my orders?" across 4 dashboards | Read-only view + written daily/weekly summary |
| Return/refund classification: agent reads return reasons across channels, classifies, drafts responses | Treating each channel's returns as a separate operational lane | HITL — agent drafts response, CEO approves |
| Dashboard collapse: the agent IS the dashboard | Dashboard fatigue / dashboard absence | Diagnostic + brief surfaces from Phase 1.x extend naturally |

**Why this isn't scope creep:**
- Phase 2 is what the prior `.deprecated/api/` build was *trying* to do. The prior build failed because it competed with incumbents (Veeqo, Sellbrite, Linnworks, ChannelAdvisor) on their feature surface. Phase 2 of the new Copio wins on a different axis: **catalog source-of-truth + agent-native HITL + trust earned in Phase 1.**
- Phase 1.6 HITL infrastructure (CEO approves agent-drafted Amazon write actions) is the foundation. Phase 2 reuses it across every channel.
- Compliance posture is the moat: Amazon's March 2026 AI Agent Policy maps onto Copio's HITL design. When Walmart and eBay publish similar policies, Copio is already compliant; incumbents retrofit.

**Buyer pool question for Phase 2:**

| Motion | Buyer | Acquisition |
|---|---|---|
| **Expansion** (compounds) | Phase 1 customer (Amazon-native CEO) who decides to add Walmart/Shopify/eBay while a Copio customer | In-product upsell, no new GTM |
| **Acquisition** (TAM unlock) | Multichannel CEO who didn't need diagnostic agent alone but needs channel-sprawl management | Net-new GTM motion |

Recommendation: lead with expansion. It compounds on Phase 1 trust, requires no new GTM, and produces the strongest case studies ("I was Amazon-only; Copio walked me into Walmart in a week"). Acquisition motion gets unlocked organically once those case studies exist.

**Note on Approach B:** This Phase 2 is essentially Approach B from the original CEO review — the agent-native ERP path the founder rejected for MVP in favor of diagnostic-only. That rejection was correct: building Approach B from day 1 puts you in a feature-checklist fight against incumbents, and you lose. Sequencing it as Phase 2 — earning trust through Phase 1 first — is good discipline, not contradiction.

## Open Questions

1. **Persona name + 5-page voice doc** — founder must drive in week 1. Suggest 90 minutes Saturday morning, drink coffee, write the voice as if writing a colleague. Alternative: run `/design-consultation` for structured naming session.
2. **What does "real value from internal usage" measurably look like?** Need to instrument: questions per week, time saved per question, decisions taken because of an answer, founder NPS on each diagnostic. Without instrumentation, the dogfood-as-validation claim is asserted not measured.
3. **External CEO commitment process** — when does the founder reach out? What's the pitch? What's the offer (free trial? Paid early access? Founding member pricing?). Phase 1.1 gating depends on this.
4. **Pricing experiment design** — $50 waitlist deposit on copio-webpage was suggested in CEO plan. Is that the right shape, or would "annual prepay $1500 for first 12 months" be a stronger commitment signal?
5. **Phase 1.0 success criteria precise definition** — at what eval score on the 20 golden questions does the founder feel comfortable promoting to Phase 1.1?
6. **Phase 2 catalog-attribute-mapping engine** — Amazon attributes → Walmart / Shopify / eBay schemas. Some attributes don't translate cleanly (e.g., Amazon "Brand Registry" vs Walmart "Brand," Amazon image rules vs eBay's). Needs its own /plan-eng-review pass before Phase 2 ships. How aggressive should the mapping be — auto-map with HITL approval, or always require CEO mapping per attribute on first sync?
7. **Phase 2 buyer-pool primary motion** — expansion vs acquisition. The recommendation in the Phase 2 vision section is "lead with expansion," but this is a strategic call worth revisiting once Phase 1.1 has 5-10 customers and we see whether Amazon-native CEOs naturally want multichannel within a quarter.
8. **TikTok Shop** — fastest-growing channel, currently absent from Phase 2 scope. Has its own agent rules + content moderation surface. Phase 2.5 or Phase 3? Worth a separate decision once Phase 2 ships.

## Success Criteria

**Phase 1.0 (founder dogfood)**:
- Phase 1.0 diagnostic agent answers ≥80% of founder's own ad-hoc Amazon questions over a 2-week trial
- ≥3 decisions per week taken because of an agent answer (instrumented, not self-reported)
- Founder reports preferring the agent over manual swivel-chair interpretation
- Eval scores ≥7.5/10 on 20 founder-authored golden questions
- p99 diagnostic latency <180s

**Phase 1.1 (productized) gating**:
- All Phase 1.0 success criteria met for ≥4 weeks
- 3 external CEOs commit to pay $199-499/mo (or $50 deposit / $1500 annual prepay)
- Eval scores hold at ≥8.5/10 on 60 golden questions with cross-tenant contamination probe at zero hits

## The Assignment

**Run one diagnostic by hand RIGHT NOW with Claude + your real SP-API data.** Pick the most interesting "why is X happening this week?" question on your mind for Nutragroup. Open Claude. Pull your relevant SP-API reports manually. Paste them in. Ask Claude to write the diagnostic in honest prose with citations and uncertainty markers. **Time it.**

Then notice three things:
1. **What was annoying about doing it manually?** (That's your build priority list.)
2. **What did Claude get wrong, and what did it get surprisingly right?** (That's your eval set seed.)
3. **What did you actually want from the answer that you didn't ask for?** (That's the persona voice spec.)

This takes 30-60 minutes. It is the highest-information-per-dollar action you can take this week, and it sits before any code. Do not skip it. The founders who skip the manual run always end up rebuilding their prompt three times.

## Eng Review Locked Decisions (added rev 3, 2026-05-08)

Full architecture decisions persisted in the CEO plan; summary here for design-doc cohesion.

- **Stack**: Inngest (workers/agent runtime); vanilla Postgres self-hosted (laptop dev → AWS production); pgvector (HNSW); Anthropic SDK direct; python-amazon-sp-api; Vercel AI SDK `useChat` for streaming.
- **Eval rig**: DIY Python — the moat is owned end-to-end. 4 explicit prompt-cache breakpoints (tools / persona / system / memory snapshot). Cache-hit-rate ≥80% verified by eval rig itself.
- **Multi-tenant**: Postgres RLS + service-layer assertion + integration test attempting cross-tenant write. Defense in depth.
- **Audit log**: single table with hash chain, Postgres trigger blocks UPDATE/DELETE.
- **Phase 2.0 mapping engine**: hybrid (rule-based deterministic 70% + LLM-assisted ambiguous 30% + untranslatable detection + persistent decision memory).
- **Cost budget**: graceful degradation per tenant — warn at 80%, refuse at 100%, admin override.
- **Feedback Loop 1** (production → dev signals): Phase 1.1 ships `events` + `daily_signals` + Slack alerts on P0/P1. Triage agent + auto-PR loop = Phase 2+.
- **Feedback Loop 2** (AI agents drafting PRs): Phase 3+, tightly scoped (prompts + tests + docs only). Forbidden: core logic, schemas, RLS, audit log code, persona voice doc, eval rig itself. All DRAFT with human review. Cost budget per finding.
